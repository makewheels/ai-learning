Hermes 自我改进

一句话:Hermes 不改模型权重,靠一条 turn 后自动跑的后台 review,把经验写进记忆(硬事实)和技能(流程),下次按需取用。下面用图 + 真实例子讲,少废话。

学习循环 记忆长什么样 写满怎么解 踩坑→技能卡 三层分工

学习循环:一个会复盘的同事

每做完一件事退一步复盘:「哪条弯路别再走?这套流程值不值得存成操作卡?」硬事实写便利贴(记忆,空间有限得合并),流程写操作卡(技能,用到才翻)。
实例 1 · 循环完整跑一轮(从「被纠正」到「下次不再犯」)
turn       user: 别用 sudo 跑 docker,我在 docker 组
review     turn 结束 → 后台重放对话,判定这是「可复用的纠正」
写入       memory add → "user is in docker group; run docker without sudo"
下次会话   该条已在冻结快照里 → agent 直接不加 sudo

记忆长什么样:两个有硬上限的文件

实例 2 · 会话开始时注入 system prompt 的「冻结快照」(原样)
════════ MEMORY (your personal notes) [67% — 1,474/2,200 chars] ════════
User's project is a Rust web service at ~/code/myapi using Axum + SQLx
§
This machine runs Ubuntu 22.04, has Docker and Podman installed
§
User prefers concise responses, dislikes verbose explanations
→ 头部带用量 %,条目用 § 分隔;会话中途不变,本会话 add 的下次才出现
~/.hermes/memories/
├── MEMORY.md   # agent 自己的笔记,上限 2200 字符(~800 tokens)
└── USER.md     # 用户画像,上限 1375 字符(~500 tokens)

~/.hermes/skills/                 # 技能(流程),唯一事实来源
├── devops/
│   └── deploy-k8s/
│       ├── SKILL.md              # When to Use / Procedure / Pitfalls / Verification
│       └── references/           # 细分文档,skill_view 按需加载
└── .hub/                         # Hub 状态:lock / quarantine / audit.log

工具只有 add / patch / remove(没有 read——自动注入;没有 replace——整条覆盖会误删多事实条目)。技能用渐进披露省 token:skills_list → skill_view → 读某个 reference。

写满怎么解:报错逼 agent 自己腾地方(偏「硬」)

实例 3 · 写满时的真实报错 + agent 的修复 batch
工具返回
  {"success":false,
   "error":"Memory at 2,100/2,200 chars; adding this entry (250 chars)
            would exceed the limit by 153 chars. Retry as ONE 'operations'
            batch that removes or shortens (patch) stale entries ...",
   "usage":"2,100/2,200"}
agent 的修复(一个 batch;上限只校验最终结果)
  {"target":"memory","operations":[
    {"action":"remove","old_text":"has Docker and Podman installed"},
    {"action":"patch","old_text":"prefers concise responses",
                       "content":"prefers terse replies"},
    {"action":"add","content":"staging SSH port 2222, key ~/.ssh/staging_ed25519"}
  ]}

踩坑 → 技能卡:「教训不是流水账」

实例 4 · 一次事故如何变成 SKILL.md 里的一条 Pitfall
会话里的坑  直接 kubectl apply,没先 diff,把 prod 覆盖了
固化进技能  ## Pitfalls
              - 先 kubectl diff 再 apply:apply 是声明式全量提交、不回滚,
                直接打 prod 会覆盖线上
要点        一句可泛化规则 + 一句为什么;不写 PR 号 / 日期 / 聊天原文

技能由 skill_manage(create/patch)维护;后台 curator 也会 consolidate。想锁住某个技能不被 agent 改:hermes curator lock <skill>。
