Agent 记忆机制研究 · 2026

Codex × Hermes
记忆怎么生成、更新、打架

两套代表性方案:OpenAI Codex 把记忆当成「后台 nightly 整理」,写进 ~/.codex/memories/ 的固定 markdown 文件;Nous Research 的 Hermes 把记忆当成「随用随记的同事」,靠一条 turn 后自动跑的学习循环,把经验固化成记忆和技能。下面用机制图拆开讲。

Codex(OpenAI) Hermes(Nous Research)
一句话对比 Codex 记忆 目录与分点 冲突处理 Hermes 自我改进 容量协商 三层记忆 并排对比 来源

先说一个反直觉的共同点

大家默认「AI 记忆 = 向量数据库 + 语义检索」。这两家的原生记忆都不是。Codex 召回是「整读一份摘要文件 + 需要时 grep 正文」;Hermes 召回是「把记忆作为冻结快照塞进 system prompt + 用 SQLite 全文检索(FTS5)翻旧对话」。两边都选了纯文件 / 全文检索,可预测、可读、可手改。真正的向量语义检索是外挂层(Mem0、Honcho、Hindsight 等)才加进来的。

差异
真正的分水岭不在「存哪」,而在什么时候写、由谁调和冲突:Codex 是延迟、后台、双模型合并(会话空闲 6 小时后才整合);Hermes 是即时、每轮后、agent 自己动手(turn 一结束就跑 review,还能当场改技能)。

Codex:两层记忆

Codex(2026 年有 CLI / IDE 插件 / ChatGPT 里的云端三种形态,共用一个 ~/.codex/ 配置目录)把记忆干脆地劈成两层,各干各的活:

打个比方:AGENTS.md 是你自己手写、贴在显示器边上的过塑规则卡——每次开工先读一遍,agent 无权改它;Memories 是夜里的整理阿姨——你下班走后,她把你一天散落的便签挑出有用的,合并进一份干净的摘要,第二天你来直接看摘要。

Memories 是怎么「生成 + 更新」的

这是你问的核心。它不是在一轮对话结束时顺手写,而是一条延迟、后台、两阶段的流水线——用两个模型:一个负责「挑出值得记的」,另一个负责「和旧记忆合并」。冲突就在合并那一步被消化掉。

开关
Memories 默认关。开:~/.codex/config.toml 里 [features] memories = true,或桌面端 Settings ▸ Personalization ▸ Enable memories。会话内 /memories 控制「本会话能否用旧记忆 / 能否喂给未来」。两个独立开关:use_memories(读入)、generate_memories(写入),可以只读不写或只写不读。

「以目录和分点形式保存」长这样

你提到的「目录 + 分点」正是 Codex 的存储形态:没有数据库、没有嵌入索引,就是 ~/.codex/memories/ 下一组固定名字的 markdown 文件。每条记忆是文件里的分点条目。

~/.codex/memories/
├── memory_summary.md      # 下次会话最先「整读」的整合视图(会被截断到预算内)
├── MEMORY.md              # 长期合并后的记忆正文;需要细节时 grep 它
├── raw_memories.md       # 整合前的原始抽取输出
├── skills/
│   └── <name>/SKILL.md   # 与某个技能相关的记忆
└── rollout_summaries/
    └── <slug>.md         # 每个会话的摘要,喂给整合流程

这组文件被官方定位为「Codex 托管的生成态」:你可以打开看,但不建议手改作为主要控制手段——要改稳定规则,请去改 AGENTS.md。(对比一下:Hermes 的同类文件恰恰鼓励 agent 主动编辑,这是两家哲学最大的不同。)

Codex 怎么处理记忆冲突

Codex 没有「精确去重表」或「版本号比对」那种确定性冲突解决。它把冲突交给模型 + 时间两件事:

  • 合并即调和(主力)。Phase 2 的「整合子代理」(模型 B)拿到新候选和整份旧记忆库,由它判断谁覆盖谁、哪些该并成一条,然后写出 diff。矛盾的事实由这个 LLM 步骤「读上下文后裁决」,而不是规则引擎。
  • 全局锁防并发。合并前获取一把全局锁,保证同一时刻只有一个整合在写 ~/.codex/memories/,避免两个后台任务互相覆盖(这是「写冲突」,区别于「内容冲突」)。
  • 衰减清理过时。30 天未被召回的单条记忆被剪除、30 天未用的 rollout 被老化淘汰。过时/失效内容靠「用不到就淡出」自然清掉。
  • AGENTS.md 用「就近覆盖」。静态层不靠合并:从 git 根走到当前目录,沿途 AGENTS.md 按路径顺序拼接;同目录的 AGENTS.override.md 优先于旁边的 AGENTS.md——层级越深、越具体的说了算。
代价
因为冲突是 LLM 裁决 + 时间衰减,所以「你 4 点的决定 4 点半不一定在」;而且生成态不保证可手工精修。想要确定性、跨机器、跨工具的冲突控制,官方路径之外要上 Mem0 / MemoryRouter / Cognee 这类外挂层(它们才提供 update_memory / delete_memory 这类显式工具和语义检索)。

Hermes:一条会自我改进的闭环

Hermes 的卖点是「唯一内置学习循环的 agent」。它不靠改模型权重变强,而是靠:从经验里造技能、用的时候磨技能、翻自己过去的对话、跨会话越攒越懂你。核心是一条 turn 结束后自动跑的后台自我改进 review。

打个比方:Hermes 像一个会记「经验教训」的同事。每做完一件事,他会退一步复盘:「这次哪条弯路别再走了?这套流程值不值得存成一张操作卡?」然后把硬事实写进便利贴(记忆,空间有限所以得合并),把可复用流程写成一张操作卡(技能,用到才翻)。下次开工,便利贴已经贴在他眼前,操作卡放在抽屉里按名字取。

技能(skill)长什么样:又是「目录 + 分点」

Hermes 的技能存在 ~/.hermes/skills/(唯一事实来源),按分类分目录;每个技能是一个文件夹,核心是一份 SKILL.md——YAML 头 + 固定分点小标题。agent 通过 skill_manage 工具自己建、自己改、自己删。

~/.hermes/skills/                 # 唯一事实来源
├── devops/
│   └── deploy-k8s/               # agent 自建的技能
│       ├── SKILL.md              # 主指令(必需)
│       ├── references/           # 细分文档,skill_view 按需加载
│       └── scripts/ templates/ assets/
├── .hub/                         # Skills Hub 状态:lock / quarantine / audit.log
└── .bundled_manifest             # 内置技能来源哈希(判断你有没有改过)

~/.hermes/memories/
├── MEMORY.md   # agent 自己的笔记,上限 2200 字符(~800 tokens)
└── USER.md     # 用户画像,上限 1375 字符(~500 tokens)
# SKILL.md 的「分点」骨架
---
name: my-skill
description: 一句话说清这技能干嘛(≤60 字符)
---
## When to Use      # 触发条件
## Procedure        # 1. 2. 3. 有序步骤 + 能跑通的命令
## Pitfalls         # 已知失败模式与修法(规则 + 一句为什么)
## Verification     # 怎么确认它成了

加载用「渐进式披露」省 token:skills_list() 只给名字+描述(约 3k tokens)→ 真要用才 skill_view(name) 读全文 → 更细再 skill_view(name, path) 读某个 reference 文件。所以查询成本只跟「答案」成正比,不跟「资料总量」成正比。

Hermes 怎么处理记忆冲突 / 写满

Hermes 的记忆是硬上限的(MEMORY 2200 字符、USER 1375 字符),而且不自动压缩。它的冲突处理比 Codex「确定性」得多——满了直接报错,逼 agent 自己腾地方:

Hermes 的三层记忆(按「粒度 / 成本」分工)

分工逻辑:「必须随时在眼前」的进记忆(小而贵),「用到才翻」的进技能(大而按需),「万一要查旧账」的交给全文检索(无限而免费)。Hermes 官方文档明确:整个记忆系统是围绕「一次会话结束」这一刻设计的——所以它建议你在自然边界敲 /new,循环 forget → recall → search 才转得起来。

再上一层
还有个伴生框架 hermes-agent-self-evolution:用 DSPy + GEPA(Genetic-Pareto 提示进化)从真实执行轨迹里自动重写技能文件,只要 API 调用、不用 GPU。这是「自动进化 skill」的激进版。也有批评声音(Towards AI)说这更像「字符串变异」而非真正的学习——把它当成「用进化搜索调 prompt/技能文本」来理解比较稳妥。

一句话
Codex = 「事后由两个模型把散乱会话合并成一份只读摘要,冲突靠模型调和 + 时间淡出」。Hermes = 「每轮后 agent 亲手把经验写进有硬上限的记忆和可增改的技能,冲突靠『满了报错、自己腾地方』和审批闸门兜底」。前者省心但滞后、不可精修;后者即时可控,但要你管好边界(敲 /new)和审批。
